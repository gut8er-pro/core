# Signup Flow UX Improvements

Two UX improvements to the 5-step signup wizard, raised together during triage.

## Context

The signup wizard (`Account → Personal → Business → Plan → Integrations`) is backed by
a Zustand signup store and finalized by the `completeSignup` server action, which creates
the Supabase auth user, the Prisma `User`/`Business` records, and a Stripe Checkout session.

Two problems with the current flow:

1. **Email-taken detection happens too late.** The only "email already exists" check runs
   inside `completeSignup` — i.e. after the user has completed every step. A user with an
   already-registered email fills out the whole wizard before being told.

2. **DAT integration is a full wizard step.** The Integrations (DAT) step adds friction to
   onboarding. It should be removed from the flow for now, with the code preserved for a
   future re-introduction. Note: this step is also where `completeSignup` is currently
   triggered, so removing it requires relocating account creation to the Plan step.

## Tickets

- `issues/01-early-email-exists-check.md` — enhancement, ready-for-agent
- `issues/02-remove-dat-integration-step.md` — enhancement, ready-for-agent

## Triage decisions (confirmed with maintainer)

- **Ticket 01 source of truth:** the early email check uses **Supabase auth admin** (matches
  `completeSignup`'s authority; catches OAuth users who exist in auth but may lack a `User`
  row), not a Prisma `User` lookup. The final check in `completeSignup` stays as a safety net.
- **Ticket 02 finish line:** the **Plan step becomes the final step**; its CTA becomes
  "Create an Account" and fires `completeSignup` + Stripe Checkout.
