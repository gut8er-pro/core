# 01 — Check email availability on the Account step

**Category:** enhancement
**Status:** ready-for-agent

## Agent Brief

**Summary:** Detect an already-registered email during the first (Account) step of the signup wizard, instead of only at final submission.

**Current behavior:**
The signup wizard's first step (Account) collects email/password/confirm-password and advances to the next step without checking whether the email is already registered. The only "email already exists" detection lives in the `completeSignup` server action, which runs at the very end of the wizard. As a result, a user who enters an already-registered email completes every step before being told the email is taken. An unused `signup` server action (wrapping Supabase `signUp`) exists but is not wired into the wizard.

**Desired behavior:**
When the user submits the Account step, the app checks whether the email is already registered **before** advancing.
- If the email is taken, an inline error ("An account with this email already exists" or equivalent) appears under the email field and the user stays on the Account step.
- If the email is available, the wizard proceeds exactly as today.
- The submit control shows a pending/disabled state while the async check is in flight, preventing double submits.
- The authoritative duplicate-email guard already inside `completeSignup` stays in place as a race-condition safety net (an email can be registered between the early check and final submission).

**Key interfaces:**
- A new server action, e.g. `checkEmailAvailable(email: string): Promise<{ available: boolean }>` (name/shape at the agent's discretion), that queries **Supabase auth admin** as the source of truth. It must detect an email that exists in Supabase auth even if there is no corresponding Prisma `User` row — do not implement this as a Prisma `User` lookup only.
- The Account step's submit handler currently only writes form values into the signup store and navigates forward; it should additionally await the availability check and block forward navigation when the email is taken, surfacing the message through the existing email-field error slot.
- Reuse the existing user-facing wording already returned by `completeSignup` for the taken-email case, and keep it i18n-extractable via the app's next-intl setup (consistent with the other auth strings) rather than hardcoding a literal in the component.

**Acceptance criteria:**
- [ ] Submitting the Account step with an already-registered email shows an inline "email already exists" error and does NOT advance to the next step.
- [ ] Submitting with an available email advances to the next step as before.
- [ ] The check uses Supabase auth as the source of truth: an email present in Supabase auth but absent from the Prisma `User` table is still reported as taken.
- [ ] `completeSignup` still returns the duplicate-email error if the address is registered between the early check and final submission (safety net unchanged).
- [ ] The taken-email message is served through the i18n layer, not a hardcoded string.
- [ ] The submit button is disabled / shows a pending state during the check; the check cannot be double-submitted.

**Out of scope:**
- Debounced "as you type" availability checking — the check runs only on Account-step submit.
- Changes to password rules, OAuth/social signup, or any step other than Account.
- Reworking `completeSignup` beyond keeping its existing duplicate-email guard.
